# Mac 首次安装与打开指南

**请先看完本指南。只有遇到打开拦截、且确认安装包来自本项目官方 Release 时，才考虑下述处理。正常打开无需执行命令。**

![首次打开指南](images/poster-mac-install-actual.png)

## 两种方法怎么选

**确认是官方原始安装包后，可以按“方法一 → 方法二”的顺序尝试；任一种成功后就停止，不需要两个都做。** 这两种方法针对“已经放入应用程序，但首次打开被安全机制拦截”，并不能解决所有安装失败。

| 你看到的情况 | 先怎么做 | 什么时候尝试另一种方法 |
| --- | --- | --- |
| “无法验证开发者”“无法验证是否包含恶意软件” | 方法一：系统设置里的“仍要打开” | 重新尝试启动后仍没有该按钮，或仍因下载隔离标记受阻，且确认官方原包完整时，可尝试方法二 |
| “已损坏，无法打开” | 先从官方 Release 重新下载、重新放入“应用程序”；如果有“仍要打开”，可先试方法一 | 确认文件完整、问题确实是隔离标记时，再试方法二；这条命令不能修复真正损坏或被修改的文件 |
| DMG 本身打不开、下载不完整、系统或芯片不兼容、磁盘空间不足 | 重新下载、选择兼容版本或解决具体安装问题 | 两种方法都不是对应修复办法；本页命令只针对已经安装到指定位置的 `.app` |
| 明确提示“将损坏你的电脑”、检测到恶意软件或撤销授权 | 停止打开并反馈 | 不使用这两种方法忽略该类告警 |

## 先确认下载来源和安装位置

1. 只从 [zhang-jincheng/space-dictation 官方 Release](https://github.com/zhang-jincheng/space-dictation/releases/latest) 下载适用于 Apple 芯片 Mac 的 DMG。不要使用来历不明的转发包。
2. 打开 DMG，把“空格听写.app”拖入“应用程序”，然后从“应用程序”打开。
3. 当前版本尚未进行 Apple Developer ID 正式签名和公证。未上架 App Store、没有开发者签名、没有公证是不同的事情；提示本身不能证明软件安全，也不能一概当作病毒。

## 方法一：系统设置 → 隐私与安全性 → 仍要打开

确认软件来自本项目官方 GitHub、且未被修改后，先尝试打开一次。遇到“无法验证是否包含可能危害 Mac 安全或泄露隐私的恶意软件”提示时，按以下步骤操作：

1. 打开 **系统设置**（如果提示框提供“设置”按钮，也可以直接点击）。
2. 点击 **隐私与安全性**（部分版本显示为“隐私与安全”）。
3. 向下滚动到页面下方的 **安全性** 区域，找到“空格听写”被阻止的提示和 **仍要打开** 按钮。
4. 点击 **仍要打开**。

如果系统要求登录密码、触控 ID 或再次确认，请按提示验证，再点击 **打开**。完成后即可再次尝试打开软件；这类“无法验证”提示通常无需运行终端命令。如果看不到“仍要打开”，先重新尝试打开应用，再返回此页；受单位管理的电脑可能限制该选项。

这是 [Apple 官方说明](https://support.apple.com/zh-cn/102445) 中提供的处理方式。

## 方法二：在终端移除该应用的下载隔离标记

**一键复制有两个入口：**

- 在本页下方的命令代码块右上角，点击 GitHub 的 **复制按钮**（鼠标移到代码块上即可显示）。复制的内容只有命令，不含说明。
- 下载 [带大号“复制 sudo 命令”按钮的安装帮助页](https://github.com/zhang-jincheng/space-dictation/releases/latest/download/Mac-Install-Guide.html)，在浏览器中打开后点击按钮。无需先打开空格听写 App。

应用已能打开时，也可进入“设置与备份”里的“Mac 首次打开”区域复制同一条命令。

适用情况：方法一没有成功，且确认仍是下载隔离标记造成的首次打开拦截。它也可能解决部分由隔离标记触发的“已损坏”提示，但不能仅凭弹窗文字认定原因。

如果提示“已损坏”，请先从官方 Release 重新下载并安装；下载不完整、文件被修改或签名失效也可能造成该提示。

若已经确认是本项目官方原始安装包、文件完整，且仍因下载隔离标记无法打开，可选择手动移除**仅这个应用**的隔离标记：

1. 在 Mac 上打开 **终端**（可用聚焦搜索“终端”）。
2. 复制以下完整一行，粘贴到终端，按回车：

```bash
sudo xattr -rd com.apple.quarantine "/Applications/空格听写.app"
```

3. 如果要求密码，输入 **Mac 登录密码**并回车。终端不会显示输入的字符或星号，这是正常现象；密码不会发送给本项目。
4. 没有报错通常表示执行完毕，再从“应用程序”打开“空格听写”。

这条命令会移除该应用及其内部文件的下载隔离标记，从而绕过对应的 Gatekeeper 隔离检查；它不会扫描病毒、修复损坏或补办 Apple 公证。**无需固定运行两遍**，重复执行通常不能解决失败原因。

- `No such file or directory`：确认应用已经放进“应用程序”，且名字确实是“空格听写.app”。
- `No such xattr`：可能已没有该隔离标记，不必反复执行；如仍打不开，应重新下载或反馈问题。
- `Operation not permitted`、其他错误或执行后仍打不开：保留报错文字，到 [Issues](https://github.com/zhang-jincheng/space-dictation/issues) 反馈；不要关闭系统整体安全保护。
- 如果系统明确提示 **“将损坏你的电脑”**、检测到恶意软件或撤销授权，请停止打开并反馈，勿用此命令忽略该类告警。

方法一是通过系统界面记录你的信任选择；方法二直接移除 `com.apple.quarantine` 扩展属性。Apple DTS 工程师也说明了[通过可信渠道传输的程序与手动移除隔离标记的适用关系](https://forums.swift.org/t/zsh-operation-not-permitted-when-trying-to-run-a-swift-executable-in-another-machine/51275)。它不是对所有“已损坏”弹窗的通用修复建议。

应用自身无法在被系统拦截、尚未启动时显示引导，因此本指南放在 GitHub 下载页和安装包旁。v1.3.0 及以后的已安装用户可在应用内确认更新；新版本发布并联网检查到更新后才会出现提醒。
